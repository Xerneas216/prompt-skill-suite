# ProCraft baseline

## Historical RED controls

These results were captured before the ProCraft name and gateway existed. They remain historical evidence for the failure that motivated the canonical PromptPackage interface. They are not fresh-context acceptance tests for v0.2.0.

1. The board-minutes summary routed the general task sensibly and kept delivery in conversation, but invented noncanonical `package`, `contract`, `prompt`, and `evaluation` structures. It also added unapproved 100-percent recall and zero-drift gates.
2. The supplier-research and approved-email case preserved write approval and did not invent a tool schema, but returned another custom outline instead of a machine-validatable PromptPackage.
3. The React dashboard diagnosis kept diagnostic work read-only and marked evaluation `not_run`, but used custom top-level and conditional fields with no deterministic JSON-to-Markdown path.

The observed failure was structural drift. Reasonable outputs still disagreed on the interface and could introduce evaluation policy that the user never requested.

Five separate fresh-context controls were `not_run` because the original session had no remaining fresh agent slots. No dynamic quality claim was made.

## Historical GREEN observation

After the canonical interface was implemented, the repeated board-minutes case returned a ready general, single-turn, conversation-only package outline with the required non-tool top-level fields. It preserved `gpt-5.6`, omitted `tool_policy`, used `not_run` for dynamic and baseline evaluation, added no persistent reasoning configuration, wrote no files, and introduced no numeric quality gate beyond the user's 300-character constraint.

This observation belongs to the earlier controller implementation. The current ProCraft gateway keeps the same canonical package behavior in Full mode and adds a smaller Fast mode for simple Prompt requests.

## Current deterministic status

For v0.2.0, the deterministic suite covers ProCraft mode and trigger contracts, PromptPackage Schema v1.0, explicit-value protection, message and tool references, dependency cycles, PTC rules, deterministic Markdown rendering, provider-neutral evaluation fixtures, clean installation, exact-hash v0.1.0 migration, publication races, and rollback.

Dynamic evaluation remains `not_run` until a fresh-context run produces execution evidence. Deterministic success must not be reported as a dynamic model-quality pass.
